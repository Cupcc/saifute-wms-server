# 月度对账需求

## Metadata

- ID: `domain-monthly-reporting`
- Status: `confirmed`
- Scope: `domain-level`
- Last updated: `2026-07-30`
- 状态说明: 当前运行时在 `reporting` 模块按 `bizDate + 自然月` 实时生成仓库侧月度对账，支持业务操作下钻、范围隔离、系统查看与 `Excel` 导出。2026-07-30 已确认删除跨物料数量和混合金额，改用分金额基础指标；月报不冻结，以财务次月一次性导出并归档的文件为正式依据。

## 主题定义

- 月度报表是 `reporting` 域的长期语义合同，用于定义“系统如何稳定地产出可核对、可追溯、可导出的月度统计结果”；它是业务真源的只读派生结果，不反向成为库存或财务写模型。
- 已完成的后续扩展规则：当 `RD_SUB` 物料强制归属研发项目后，月报必须能够把同一笔 `RD handoff` 解释成主仓视角的内部转移、研发项目视角的项目入账，以及全仓视角的内部协同，而不是继续把 `RD handoff` 与研发项目完全割裂。
- 当前已确认的一阶段优先切片，不再是“大而全月报总纲”，而是：
  - `仓库侧按月核对本期分口径金额`
  - 由仓库人员或系统内 `财务会计` 角色查看 / 导出系统报表，再与外部财务系统核对
  - 当金额不一致时，在系统内继续下钻到业务主题与单据头做排查
- 财务在次月统计上月一次，以携带统计月份的当次导出文件为正式依据；系统查询保持实时，不建设冻结、结账或报表版本。
- 第一阶段不以“历史余额已经可信”作为前提；日期范围报表和更重的分析能力仍可后续规划。

## 当前已确认的一阶段切片

### 一句话定义

- 以 `bizDate` 为归月口径，按自然月统计仓库侧本期金额：总览先分别回答`库存成本流入 / 库存成本流出 / 库存成本净变动`以及采购、销售、车间和研发项目的业务金额，再按领域展开操作汇总，并在差异出现时下钻到单据头和单据行查看金额基础、成本与来源追溯信息。数量只在单一物料或单据行粒度展示。

### 使用者

- 仓库管理员：系统内查看与导出月度对账报表，负责和财务对账及差异排查。
- 研发小仓管理员：仅在自身 `RD_SUB` 范围内查看与本仓相关的月度金额主题。
- 财务会计：系统内只读查看与导出月度对账报表，参与经营数据核对，不录入财务侧数字，也不执行自动对账或业务写入。
- 外部财务系统 / 外部财务侧：仍通过系统导出结果参与离线核对，不作为本系统的写入真源。

### 核心目标

- 以“本月发生了哪些金额变化”为核心对账对象，而不是先证明历史期初 / 期末余额完全可信。
- 生成一份仓库侧完整的月度发生金额报表，覆盖当前所有会影响仓库月度金额的业务主题。
- 顶层按金额基础提供可解释的库存成本流入/流出/净变动、采购净入库、销售净额/净成本、车间净耗用成本和研发项目净耗用成本；禁止把采购价、销售价和库存成本混成一个`总金额`。
- 第二层按业务领域展开，让仓库先按业务领域排查，而不是先按技术动作目录排查。
- 下层提供带明确名称的业务金额、库存成本和单据证据；只有单一物料汇总和单据行可以提供数量。
- 页面与导出中的用户可见名称，应与业务实际名称保持一致，例如 `领料 / 退料 / 报废 / 销售出库 / 销售退货 / 项目交接`，不使用报表层自定义黑话。

### 明确边界

- 第一阶段只生成仓库侧报表，不在系统内录入、导入或自动比对财务侧数字。
- 第一阶段不承诺修复历史余额问题，不把收发存全链闭环作为前置条件。
- 第一阶段默认追溯到单据头，不把“所有主题都必须支持单据行级下钻”写成普遍合同。
- 第一阶段不把技术性逆操作当成独立业务主题展示。
- 单据头不汇总跨物料数量；其金额列必须通过业务金额名称说明是 WMS 销售价、单据录入金额还是其他业务基础，并与库存成本列分开。
- 数量格式当前仍统一取整；真实数据已存在小数，本轮不修改，后续必须先确认按单位的精度规则。
- 研发项目成本汇总优先使用有效且未冲销库存流水成本，没有流水成本时回退已保存的行`costAmount`；两者都缺失时是否排除并标记缺失，还是回退录入`amount`尚待业务确认，确认前不得静默混用。
- 分类发生额与余额的历史分类口径尚未完全一致，本轮只记录风险与候选方案，不改数据库或分类写链路。

## 长期定位

- 本文档长期维护月报的指标语义、金额基础、方向和可追溯边界。
- 当前正式流程不是系统内冻结：查询结果可以随业务修正实时重算，财务在次月对上月执行一次导出，并归档该文件作为当次正式统计结果。
- 当前导出审计记录导出人、时间与筛选条件，但不保存文件字节、哈希或版本；以后重新查询/导出可能与已归档文件不同。业务已接受该风险，核对时以已归档文件为准。
- 只有将来出现法规审计、多人重复出表或必须在系统内复现正式文件的需求时，才重新评估快照、哈希或版本化；冻结与人工重算不再是当前路线图的强制能力。
- 日期范围报表和更多分析视角可以后续扩展，但不得重新引入跨物料数量或混合金额。

## 统计口径

### 总体原则

- 月度报表属于只读派生结果，不是库存或财务的主数据来源。
- 第一阶段报表结果应从业务单据、库存流水和成本结果中汇总生成，保证可追溯。
- 第一阶段默认按 `bizDate` 归月，且以自然月为统计周期。
- `bizDate`等数据库`DATE`字段按字面日历日期查询：起止日都是闭区间边界，不把`YYYY-MM-DD`先解释成业务时区瞬间再换算 UTC，以免月初或“今天”偏移到前一天。
- 权威金额合计必须由后端 Decimal 完成；前端将金额转成 JS `Number`只可服务于图表坐标，不可生成页面、导出或对账所依赖的权威合计。
- 数量只有在`单一物料 + 单一单位`或单据行粒度才可相加；总览、领域、单据类型、车间、销售项目、研发项目、物料分类和趋势均不得提供跨物料数量合计。
- `金额`不是统一量纲：库存来源成本、WMS 入库计价、WMS 销售价和用户录入金额必须分列或通过字段名称明确基础。
- 若未来改为按审核 / 生效日期归月，应视为正式统计口径变更，而不是实现细节微调。

### 第一阶段对账对象

- 第一阶段对账对象是：
  - `本期库存成本流入 / 流出 / 净变动`
  - `采购净入库、销售净额 / 净成本、车间净耗用成本、研发项目净耗用成本`等分口径业务金额
- 第一阶段不是以下对象：
  - 历史期初余额可信性证明
  - 收发存全链闭环
  - 财务系统内正式入账结果

### 目录结构

- 第一阶段报表采用“总览优先 + 领域优先”的结构：
  - 总览层：先回答当前筛选范围内的库存成本方向和各业务金额基础
  - 领域层：再按业务领域展开操作
  - 追溯层：最终下钻到单据头
- 第一阶段领域层应按以下稳定领域组织：
  - `入库`
  - `车间`
  - `销售`
  - `研发项目`
  - `RD小仓`
- `销售项目` 视角属于 `销售` 域下的业务汇总，不应为了展示方便把同一批销售事实重复拆成与 `销售` 并列的一级目录。

### 当前已纳入的领域与操作清单

第一阶段覆盖当前所有会影响仓库月度金额的业务事实，但页面与导出应优先按“领域 -> 操作 -> 业务汇总 / 单据”组织，而不是把动作类型直接抬成一级目录：

- `inbound / 入库`
  - 验收入库
  - 生产入库
  - 退给厂家 / 供应商退货
  - 入库调价转入 / 转出仍归属入库域，不单独升成一级域
- `workshop-material / 车间`
  - 领料
  - 退料
  - 报废
  - 车间汇总默认按 `workshop`
  - `车间净耗用成本 = 领料成本 - 退料冲回成本 + 报废成本`
- `sales / 销售`
  - 销售出库
  - 销售退货
  - 销售项目汇总至少要支持 `salesProjectId / salesProject` 项目视角，回答“销售中的每个项目发生了多少”
- `rd-project / 研发项目`
  - 项目交接
  - 项目领用
  - 项目退回
  - 项目报废
  - 研发项目汇总默认按 `rd-project`
  - 项目交接、领用、退回、报废和盘点的成本指标使用`cost / costAmount`，不得以录入`amount`冒充实际成本
  - 成本来源优先级固定为有效且未冲销库存流水成本 → 已保存的行`costAmount`；两者都缺失时的合同待业务确认
  - `项目净耗用成本 = 项目领用成本 - 项目退回成本 + 项目报废成本`
- `rd-subwarehouse / RD小仓`
  - `RD盘盈 / RD盘亏`
  - 盘点调整等 RD 内部仓务变动可以继续保留在 RD 相关读模型里，但不得替代研发项目正式入账视图
- `纠偏相关事实`
  - 调价
  - 补录影响
  - 跨月修正
  - 盘点调整
  - 上述项不单独作为一级领域；如需解释，优先通过来源追溯字段或领域内说明完成

说明：

- 这份清单的目标是冻结“当前已纳入第一阶段月度金额对账的主题范围”。
- `REVERSAL_IN / REVERSAL_OUT` 这类技术性逆操作不作为独立业务主题出现在报表目录中，应归并回原业务主题理解。

### 已完成的后续扩展：RD 小仓项目化口径

- 当 `RD_SUB` 物料全部归属研发项目后，月报不能再把 `RD handoff` 与 `rd-project` 汇总视为完全分离的两条账。
- 同一笔 `RD handoff` 在不同视角下可以有不同呈现：
  - `MAIN` 视角：可解释为主仓总出或内部转移出
  - `RD_SUB / rd-project` 视角：可解释为项目总入或交接入项目
  - 全仓总览视角：仍可视为内部转移，不应被粗暴重复并入总入 / 总出
- 视角转换必须建立在交接事实层已有项目归属的前提上，不能靠报表层按备注、车间或单据号猜项目归属。
- `RD_SUB` 明细下钻必须能显示研发项目编码 / 名称；按研发项目关键字查询时，同一项目的交接入库、项目领料、项目退料、项目报废和盘点 / 调整应能在同一视角下解释项目归属库存成本变化。

### 已完成的后续扩展：物料分类视角

- `monthly-reporting` 已在同一页面内新增 `领域视角 / 物料分类视角` 切换，不替换既有领域视角。
- 当前分类视角覆盖`验收入库 / 生产入库 / 退给厂家`、`车间领料 / 退料 / 报废`、`销售出库 / 退货`；不扩到`rd-project / rd-subwarehouse`。
- 分类金额必须基于 `stock_in_order_line`、`sales_stock_order_line`与`workshop_material_order_line`的单据行事实，不允许沿用单据头月报结果做二次 regroup。
- 入库与销售发生额优先采用业务发生时的单据行分类快照；车间发生额和月初/月末余额当前仍读取物料现分类。该差异是已知历史稳定性风险，不得再宣称所有分类指标都已由历史快照稳定。
- 汇总规则固定为“单据行只归属一个稳定最终分类”；`未分类` 必须作为稳定分类参与汇总。
- 分类总览和分类行只展示金额及单据/行数；物料行与单据行因已有单一物料和单位，可以保留数量。
- 历史分类修复本轮不实施。若后续只要求稳定的时点分类，优先建设 SCD2 物料分类归属历史；若还要求每个分类满足期初、转入转出与期末恒等，应同时建设显式分类转移台账。

### 展示与追溯合同

- 总览层默认以 `金额` 为主，至少回答：
  - `业务单据数`
  - `库存成本流入 / 库存成本流出 / 库存成本净变动`
  - `验收入库计价金额 / 生产入库计价金额 / 退给厂家金额 / 采购净入库金额`
  - `销售净额（WMS 销售价） / 销售净成本`
  - `车间净耗用成本 / 研发项目净耗用成本`
- 领域层默认展示：
  - 该领域的操作汇总
  - 该领域对应的业务汇总
- 业务汇总至少覆盖 `车间 / 销售项目 / 研发项目` 等真实业务锚点；项目交接已并入研发项目汇总，不再保留独立历史桶。
- 车间汇总展示领料成本、退料冲回成本、报废成本和净耗用成本；销售项目展示销售价金额、成本金额、净额、净成本和 WMS 商品毛利估算；研发项目展示交接入成本、领退报废成本、净耗用成本和项目归属库存成本净变动。
- 单据头层默认展示`业务金额基础 + 业务金额 + 库存成本流入/流出/净变动`，不展示跨物料数量。业务金额基础必须能区分`WMS 销售价金额`、`单据录入金额`等含义。
- 单据行和物料汇总层可以展示数量、单位、成本单价、成本金额，以及销售业务的销售价/销售金额。
- 单据层默认最小追溯粒度是 `单据头`。
- 若需要解释跨月来源或历史引用，优先通过 `来源月份 / 来源单据` 等来源追溯字段完成，不把异常标识写成必需合同。
- 物料分类视角属于 follow-on 分支：
  - 总览至少回答`验收入库计价金额 / 生产入库计价金额 / 退给厂家金额 / 采购净入库金额`、车间领退报废与净耗用成本、销售出退的销售价与成本金额、WMS 商品毛利估算，以及月初、净变动和月末库存成本
  - 销售类金额必须同时区分销售价口径和库存成本价口径：`sales_stock_order_line.amount` 归入销售价金额，`sales_stock_order_line.costAmount` / 库存来源成本归入成本价金额
  - 分类汇总必须按单层分类展示，不使用分类路径、祖先链或父级树形汇总
  - 分类明细的默认最小追溯粒度是 `单据行`，并展示该行稳定最终分类
- 第一阶段至少要能回答：
  - 当前仓库本月库存成本流入/流出由哪些领域构成，各业务金额基础分别是多少
  - 某个领域下某个车间 / 销售项目 / 研发项目本月金额由哪些单据构成
  - 哪张单据可能是差异来源

### 技术逆操作规则

- `REVERSAL_IN / REVERSAL_OUT` 不作为独立业务主题展示。
- 若报表需要保留相关痕迹，应在来源说明或领域说明中解释其归并关系。

## 长期约束

- `C1` `reporting` 继续保持只读聚合定位，不拥有事务写模型。
- `C2` 第一阶段默认按 `bizDate` 归月，以自然月为统计周期。
- `C3` 第一阶段仅产出仓库侧报表，允许系统内 `财务会计` 只读查看和导出，不做财务侧数据回填、导入或系统内自动差异比对。
- `C4` 第一阶段默认追溯到单据头，不把单据行级追溯作为所有主题的通用要求。
- `C5` 第一阶段顶层先回答库存成本方向及采购、销售、车间、研发项目等分口径金额，领域层再按业务领域展开；数量只作为单一物料或单据行证据。
- `C6` 纠偏类金额保留在原业务领域内，不再把异常标识或异常栏目作为必需合同；若需解释，优先依赖来源月份 / 来源单据等追溯字段。
- `C7` 技术性逆操作不应污染业务领域目录，也不应把异常类动作抬成主领域。
- `C8` 系统需要支持系统内查看与 `Excel` 导出，便于仓库、系统内财务会计与外部财务侧离线核对。
- `C9` 月报查询保持实时；财务在次月一次性导出上月结果并归档该文件。当前不要求系统内冻结、结账、版本化或人工重算结果沉淀。
- `C10` 当 `RD_SUB` 实施项目化归属后，月报必须按视角重算 `RD handoff` 的入 / 出归类，并把项目交接直接并入研发项目入账，不能再通过单一固定“交接金额”列掩盖项目入账语义。状态：`已完成`
- `C11` 物料分类发生额应优先使用业务时点分类快照；当前车间发生额与余额仍有读取`material.categoryId`的已知例外。本轮不修改，页面与文档必须披露历史分类漂移风险。
- `C12` 所有跨物料数量聚合均为非法合同；如果未来需要高层数量，只能按单位分组并明确量纲，不能恢复单一“总数量”。
- `C13` 混合`总金额 / 净发生金额`均为非法合同；字段名和帮助文案必须说明库存成本、WMS 入库计价、WMS 销售价或录入金额基础。
- `C14` 权威金额合计由后端 Decimal 返回；前端浮点计算不得成为页面、导出或财务核对的金额真源。
- `C15` 车间与研发项目净耗用统一为`领用成本 - 退回成本 + 报废成本`；研发成本指标使用实际`cost / costAmount`。
- `C16` 数据库`DATE`字段使用字面日历日期闭区间；首页“今天”、趋势显式范围和自然月边界不得因业务时区到 UTC 的瞬间换算发生跨日偏移。

## 查询与导出

- 第一阶段报表需要支持系统内查看，不应只依赖导出文件。
- 第一阶段报表需要支持 `Excel` 导出，供仓库、系统内财务会计与外部财务侧离线核对。
- 导出文件必须携带统计月份；财务次月完成一次导出并归档后，该文件是当次正式统计依据，后来实时查询或重导结果不得覆盖归档件。
- 查询至少支持按月、按仓别、按车间 / 归属维度、按业务领域 / 操作过滤。
- 主仓与 `RD_SUB` 小仓仍需按现有范围隔离查看，不默认把主仓运营面数据暴露给小仓管理员。
- 第二层单据头清单复用业务单据共性字段；除本文件已规定的金额基础、成本方向和禁止跨物料数量外，主题专属字段可在后续任务中扩展。

- 在系统内导入财务侧对账文件。

- 把 `REVERSAL_IN / REVERSAL_OUT` 做成独立业务主题展示。
- 为每个业务主题一次性写死所有单据头专属字段。
- 系统内月报冻结、结账、结果快照、文件哈希或版本化。

- 建设 SCD2 分类归属历史或显式分类转移台账。
- 实时数仓或复杂 `OLAP` 分析体系。

## 功能项说明

### `F1` 分金额基础月度汇总

- 这项功能要解决什么：先把“本月发生了哪些金额变化”按可解释的金额基础稳定统计出来，避免把采购价、销售价和库存成本相加。
- 明确不包括什么：不先修复历史余额，不先做收发存全链闭环。
- 完成标准：
  - `[TC-1]` 报表按 `bizDate` 归月。
  - `[TC-2]` 报表以自然月为统计周期。
  - `[TC-3]` 总览显示库存成本流入、库存成本流出和库存成本净变动。
  - `[TC-4]` 总览分别显示验收入库计价、生产入库计价、退给厂家、采购净入库、销售净额、销售净成本、车间净耗用成本和研发项目净耗用成本。
  - `[TC-5]` 总览、领域、单据类型和业务汇总均不显示跨物料数量。
  - `[TC-6]` 后端使用 Decimal 生成权威金额合计，前端不以 JS `Number`重算财务合计。
  - `[TC-7]` 首页“今天”、趋势日期范围和自然月使用数据库`DATE`字面日期闭区间，不发生业务时区跨日偏移。

### `F2` 领域优先目录与业务汇总

- 这项功能要解决什么：把第一阶段实际纳入的业务领域冻结为可执行清单，并按业务实际名称组织汇总。
- 明确不包括什么：不在此阶段承诺未来尚未进入仓库月度核对流程的新主题。
- 完成标准：
  - `[TC-1]` 第一层目录按业务领域稳定组织，而不是按动作方向组织。
  - `[TC-2]` 领域内操作覆盖当前所有会影响仓库月度金额的业务家族。
  - `[TC-3]` 第二层至少能回答 `车间 / 销售项目 / 研发项目` 等关键业务锚点，项目交接通过研发项目视角解释。
  - `[TC-4]` 技术逆操作和异常类动作不作为独立主领域出现。

### `F3` 领域汇总到单据头追溯

- 这项功能要解决什么：让金额不一致时，用户能快速定位问题单据。
- 明确不包括什么：不要求所有主题默认细到单据行。
- 完成标准：
  - `[TC-1]` 用户可从领域汇总和车间 / 销售项目 / 研发项目汇总下钻到单据头清单，项目交接通过研发项目视角下钻。
  - `[TC-2]` 单据头层默认展示业务金额基础、业务金额和库存成本方向，不汇总跨物料数量；物料或单据行层可以展示带单位的数量。
  - `[TC-3]` 用户能据此判断差异来源单据。

### `F9` 物料分类视角月度对账

- 这项功能要解决什么：在既有领域视角之外，为仓库提供一套按物料分类核算月度发生金额的明确视角，回答“本月各分类的入库计价、销售、车间耗用和库存成本变化分别是多少”。
- 明确不包括什么：不把分类视角扩到研发项目/RD小仓；本轮不建设分类归属历史或分类转移台账。
- 完成标准：
  - `[TC-1]` 月报页面在既有领域视角之外，新增 `物料分类视角` 切换。
  - `[TC-2]` 分类视角覆盖`验收入库 / 生产入库 / 退给厂家`、`车间领料 / 退料 / 报废`、`销售出库 / 销售退货`。
  - `[TC-3]` 分类金额按单据行事实只归属一个最终分类；`未分类`被纳入，且不向祖先分类汇总。
  - `[TC-4]` 分类总览和分类行只展示金额、业务单据数和单据行数；数量只出现在单一物料和明细行。
  - `[TC-5]` 车间净耗用成本包含报废，并使用`领料成本 - 退料冲回成本 + 报废成本`。
  - `[TC-6]` 页面和文档明确发生额快照与当前分类余额可能不一致，不把历史分类稳定性作为已完成能力。

### `F5` 仓库侧查看与导出

- 这项功能要解决什么：让仓库和系统内财务会计能直接拿系统结果去和外部财务侧核对。
- 明确不包括什么：不在系统内录入、导入、自动比对财务数据。
- 完成标准：
  - `[TC-1]` 报表支持系统内查看。
  - `[TC-2]` 报表支持 `Excel` 导出。
  - `[TC-3]` 导出结果可被系统内财务会计和外部财务侧核对使用。

### `F6` 正式导出归档流程

- 这项功能要解决什么：在不冻结系统查询的前提下，明确财务使用哪一份结果完成当月核对。
- 完成标准：
  - `[TC-1]` 财务在次月对上月执行一次导出，导出文件携带统计月份。
  - `[TC-2]` 当次文件由财务归档并作为正式依据；后来实时查询或重导不覆盖归档件。
  - `[TC-3]` 当前系统不承诺保存导出文件字节、哈希或正式版本，也不承诺从系统内复现归档文件。
- 若未来法规或审计要求必须在系统内复现正式文件，应另立需求评估快照/哈希/版本化，不能默认改变当前流程。

### `F8` RD 小仓项目化口径与视角重算

- 这项功能要解决什么：当 `RD_SUB` 小仓改为“每笔物料都必须归属研发项目”后，让月报能够从主仓、`RD_SUB` 与研发项目三个视角一致解释同一笔交接事实。
- 明确不包括什么：不在报表层按备注 / 单据号 / 车间猜项目归属；不把研发项目提升为新的 `stockScope`。
- 完成标准：
  - `[TC-1]` 文档明确同一笔 `RD handoff` 可在不同视角下呈现为主仓总出、研发项目总入或全仓内部转移。
  - `[TC-2]` 文档明确这些视角都建立在交接事实层已有项目归属的前提上，而不是报表层事后推断。
  - `[TC-3]` 导出与下钻在项目化口径下仍保持可追溯。
  - `[TC-4]` 研发项目汇总可同时解释交接入项目和后续项目领退报废，不再把主仓到 RD 交接作为与研发项目割裂的平行账。

### `F7` 日期范围报表语义分离

- 这项功能要解决什么：保留临时日期范围分析能力，同时不把它误作按自然月生成的月报。
- 当前状态说明：保留为后续阶段能力，不是第一阶段首要交付。

## 待确认

- 历史研发交接或项目动作同时缺少有效未冲销库存流水成本和已保存的行`costAmount`时，是显示缺失并排除成本合计，还是回退使用录入`amount`；确认前不得静默混用。
- `个 / 卷`等离散单位出现小数是否为合法业务数据，以及每种单位允许的显示精度；确认前保持当前取整格式。
- 是否存在必须让每个物料分类满足`期初 + 本期转入 - 本期转出 = 期末`的财务要求；只有该要求成立时，才需要在 SCD2 之外增加显式分类转移台账。
