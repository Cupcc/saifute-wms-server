## 审查时一句话结论（2026-07-29 基线）

审查时的报表不是“所有数字都算错”，而是存在三类问题：

1. **名称直接错误**：`净生产`把验收入库、生产入库、退给厂家混成生产概念，应删除或拆分。
2. **数学上能相加，业务上不能相加**：跨物料单位汇总数量，以及把采购/库存成本、销售价、内部成本混成`总金额`，都不能作为可靠对账指标。
3. **公式与既有领域真源冲突**：车间净耗用应为`领料 - 退料 + 报废`，审查时一个页面取了相反数，另一个页面又漏掉报废。

因此，审查时的报表更适合作为“业务事实浏览器”，还不能把所有顶层合计直接视为仓库账或财务账。

截至 2026-07-30，上述三类问题均已按业务决定完成主体实现：`净生产`和跨物料数量已删除，金额基础已拆分，车间/趋势/首页/库存健康/Decimal 合计已对齐，并通过真实 7 月数据与浏览器验证。当前唯一未闭环项是研发实际成本两种来源都缺失时的业务处理。

## 判定标记

| 标记 | 含义 |
| --- | --- |
| `正确` | 名称、来源、方向和公式基本一致，可继续使用 |
| `有条件` | 公式可解释，但只有在限定粒度、成本覆盖或使用场景下才成立 |
| `不正确` | 名称与业务事实不符、公式缺项、粒度不可加或方向错误 |
| `低价值` | 技术上成立，但对仓库或财务决策帮助很小，建议降级或移除 |

## 业务审核结论（2026-07-30）

| 编号 | 业务决定 | 本轮处理边界 |
| --- | --- | --- |
| 1 | `接受` | 彻底删除`净生产`，不保留同义改名；验收入库、生产入库、退给厂家分列，并提供`采购净入库金额 = 验收入库计价金额 - 退给厂家金额`。 |
| 2 | `接受，采用更严格边界` | 删除所有跨物料数量合计。数量只允许出现在单一物料汇总或单据行等量纲明确的层级；总览、领域、单据类型、车间、项目、分类、趋势和单据头不再展示总数量或净数量。 |
| 3 | `接受` | 删除混合`总金额 / 净发生金额`，拆成库存成本流入、库存成本流出、库存成本净变动、采购净入库、销售净额、销售净成本、车间净耗用成本和研发项目净耗用成本等明确金额基础。 |
| 4 | `先调查，不修改` | 已确认真实数据存在小数数量；本轮继续保留`formatQuantity().toFixed(0)`的现状，不改 API、页面或导出格式。后续应先确认不同计量单位允许的小数规则。 |
| 5 | `接受` | 车间统一使用`净耗用 = 领料 - 退料 + 报废`，金额字段明确为实际来源成本。 |
| 6 | `接受` | 趋势`业务单据数`按`单据类型 + 单据 ID`去重；趋势不再汇总跨物料数量，并拆开 RD 交接、盘盈、盘亏等不同事实。 |
| 7 | `接受` | 首页把验收入库、生产入库、退给厂家分开；退厂不能正向抬高入库金额，采购净入库按验收扣退厂计算。 |
| 8 | `接受` | 库存健康统一在`物料 × 仓别`粒度计算，状态拆成`低库存 / 正常 / 超上限 / 未配置`。 |
| 9 | `接受实际成本口径` | 研发项目交接、领用、退回、报废和盘点汇总使用`cost / costAmount`，不再把录入`amount`称为成本；历史记录缺少成本时是否回退录入金额仍待业务确认。 |
| 10 | `保持实时、不冻结` | 财务在次月统计上月一次，以携带统计月份的导出文件为准；保留当前按自然月实时重算的实现，不增加结账、冻结或版本化。 |
| 11 | `接受` | 权威金额合计由后端 Decimal 计算并返回；前端 JS `Number`只可用于图表坐标，不再生成财务合计。 |
| 12 | `只分析，暂不修` | 本轮不改数据库、写链路或余额归类；记录方案比较和现存风险，待业务需要分类级收发存恒等式时另立任务。 |

除上述边界外，审查表中关于字段名称、金额基础、方向和帮助文案的建议均已接受；实现和验收进度以`task-20260730-reporting-metric-semantics-alignment.md`为准。

### 暂缓项调查证据

#### 数量小数

- `inventory_balance`中有 7 / 1955 条小数余额。
- 有效验收/入库行有 7 / 4319 条小数数量，有效销售行有 1 / 1028 条，有效车间行有 5 / 3307 条。
- 已出现小数的单位包括：`个` 2 条、`KG` 2 条、`卷` 1 条、`升` 1 条、`米` 1 条。
- 2026 年 7 月没有小数有效业务行，但有一项 7 月报表物料的月初/月末数量分别为`256.590000 / 306.590000`；当前格式会展示为`257 / 307`。
- 结论：小数不是纯理论问题，但`个 / 卷`等单位的小数是否合法尚未确认。本轮遵照业务决定不改格式；后续应按单位定义精度，而不是再次采用全局统一精度。

#### 研发项目成本

- 既有测试样例已经证明录入金额与 FIFO 实际成本可能不同：同一事实`amount = 90`、`cost = 100`。
- 当前本地有效 RD 项目动作/交接数据为 0 行，无法用生产样本判断历史缺成本的实际覆盖面。
- 当前实现优先采用对应业务行的有效且未冲销库存流水成本；没有该流水成本时回退已保存的行`costAmount`，不会回退动作/交接录入`amount`。仓储层回归测试同时锁定了来源优先级和冲销过滤。
- 剩余开放问题只发生在上述两种实际成本来源都不存在时：当前实现会形成 0，但这尚未被接受为目标合同；应显示缺失并排除成本合计，还是回退录入`amount`，仍待业务确认。

#### 实时月报与正式导出

- 月报查询继续按所选自然月实时重算；财务流程是在次月统计上月一次，并归档当次导出文件作为正式依据。
- 当前导出文件名携带统计月份；审计日志记录导出人、导出时间和筛选条件，但不保存文件字节、文件哈希或正式版本号。
- 剩余风险：后续数据被修正后重新查询/导出，同一统计月份可能与已归档正式文件不同。当前业务流程接受该风险，因此本轮不增加冻结能力；核对时应以已归档文件而不是后来重查结果为准。

#### 历史分类方案比较

| 方案 | 优点 | 局限 | 适用结论 |
| --- | --- | --- | --- |
| 查询时一律使用当前分类 | 实现最简单，适合看“今天库存属于什么分类” | 历史月会随主数据修改漂移，且与单据行快照不一致 | 不适合作为稳定历史月报 |
| 仅按单据行分类快照重放余额 | 已发生业务可稳定归类，复用现有快照 | 无法解释分类修改本身；没有当月业务的结存或跨分类结转仍可能断裂 | 可改善发生额，不能独立保证分类余额恒等 |
| SCD2 物料分类归属历史 | 可按任意业务时点解析物料所属分类，适合稳定月初/月末快照 | 物料月中改分类时，分类 A 的月初余额会直接出现在分类 B 的月末，若没有转移动作仍不能做到分类级`期初 + 发生 = 期末` | 若只要求稳定时点分类，这是成本较低的推荐方案 |
| SCD2 + 显式分类转移台账 | 分类变更可形成旧分类转出、新分类转入，审计和分类级恒等式最完整 | 需要改写链路、迁移历史、定义生效日期与撤销规则，实施成本最高 | 若财务要求分类级收发存严格对平，这是最终推荐方案 |

现有数据中已发现 1 个物料、2 条 2026 年 4 月有效入库行的历史分类快照与当前分类不同，且该物料仍有正余额；2026 年 7 月暂未发现此类不一致。因此本轮保持现状。后续若只要求历史查询稳定，优先实施 SCD2；若要求每个分类满足`期初 + 本期转入 - 本期转出 = 期末`，应同时建设显式分类转移台账。

| 库存净发生金额 | 月末库存成本减月初库存成本 | `closingAmount - openingAmount` | 有 | 有条件 | `正确但应改名`；建议使用`库存成本净变动`，它比通用`总入金额 - 总出金额`更接近存货对账 |
| 入库数量 | 分类月报已纳入事实中的所有 IN 数量，不只是入库单 | 销售退货、车间退料、验收、生产等 IN 行求和 | 名称误导 | 无 | `不正确（名称）`；改名`纳入范围的库存流入数量`，并说明分类月报并未覆盖全部库存动作 |
| 出库数量 | 分类月报已纳入事实中的所有 OUT 数量 | 销售出库、退厂、车间领料等 OUT 行求和 | 名称误导 | 无 | `不正确（名称）`；改名`纳入范围的库存流出数量`；与库存净变动可能因漏报废/RD/调整而不相等 |

| --- | --- | --- | --- | --- | --- |

| 生产入库数量/金额 | 有效生产入库单行的数量和入库金额 | 对`PRODUCTION_RECEIPT`行求和 | 有 | 有条件 | `正确`；这才是生产入库。金额是 WMS 入库计价，不等于完整制造成本，需明确 |
| 退给厂家数量/金额 | 有效退厂单行的数量和金额 | 对`SUPPLIER_RETURN`行求和 | 有 | 有条件 | `正确`；建议统一业务名`退厂/供应商退货`，金额不等于供应商红字发票金额 |
| 净生产数量 | 当前所谓验收、生产、退厂综合净额 | `验收入库 + 生产入库 - 退给厂家` | 名称错误 | 名称错误 | `不正确`；删除。生产只保留`生产入库` |
| 净生产金额 | 当前所谓验收、生产、退厂综合净额 | `验收入库金额 + 生产入库金额 - 退厂金额` | 名称错误 | 无会计意义 | `不正确`；删除。若业务需要，新增`采购净入库金额 = 验收入库 - 退厂`，生产入库金额单列 |

### 5.3 销售、车间与分类汇总

| 当前名字 | 当前含义 | 当前如何计算 | 仓库意义 | 财务意义 | 原始审查结论与建议（已审核） |
| --- | --- | --- | --- | --- | --- |
| 分类净销售数量 | 分类下销售出库减销售退货数量 | `outboundQty - returnQty` | 分类内仍可能混多种单位 | 无 | `不正确（分类合计）`；按单位分组或删除，物料层保留 |
| 分类净销售金额 | 分类下销售出库销售额减退货销售额 | `outbound sales amount - return sales amount` | 有 | 有条件 | `正确`；改名`分类销售净额（WMS销售价）` |
| 车间领料/退料金额 | 分类月报中车间行的`amount` | 聚合单据行`amount`，实际成本另在`costAmount` | 可能不是 FIFO 实际成本 | 不可靠 | `不正确（帮助文案称成本）`；改用`entry.cost` |
| 车间净使用 | 分类月报当前为领料减退料 | `pick - return` | 漏报废 | 漏报废 | `不正确`；纳入报废并统一改名`车间净耗用` |
| 单据行数 | 当前筛选范围内纳入分类月报的业务行数 | `entries.length` | 有：核对明细完整性 | 有：辅助 | `正确`；不应把数值高低本身标为危险 |
| 单据数量 | 当前筛选范围内业务单据去重数 | 按`documentType + documentId`去重 | 有 | 有 | `正确`；页面名称统一为`业务单据数` |

### 5.4 分类归属风险

当前发生额与余额不是同一套分类时间口径：

- 验收、生产、销售发生额使用单据行上的历史分类快照。
- 车间领退料和月初/月末余额查询使用物料当前分类。
- 当物料后来改分类时，同一个物料的本月发生、月初和月末可能被分到不同分类。
- 余额再按`分类 + 物料`与发生额求交集，分类不一致时，该物料的月初/月末甚至会显示为 0。

因此，分类层的`月初 / 月末 / 库存净发生`目前只能标记为`有条件`，在历史分类变化场景下不能作为稳定月报合同。

## 7. 建议采用的目标指标词典

以下词典已随 2026-07-30 业务审核被接受；数量字段仍受“仅单一物料粒度可汇总”的约束，数量显示精度本轮暂不调整。

| 建议名字 | 建议含义 | 建议公式 | 建议展示粒度 |
| --- | --- | --- | --- |
| 生产入库数量/成本 | 生产完工后进入仓库的真实入库 | 仅`PRODUCTION_RECEIPT` | 物料 + 单位；金额可按车间/分类汇总 |
| 验收入库数量/入账价金额 | 外部采购/验收形成的入库 | 仅`ACCEPTANCE` | 物料 + 单位；金额可按供应商/分类汇总 |
| 采购净入库金额 | 验收入库扣除退厂 | `验收入库金额 - 退厂金额` | 月份 + 仓别；需注明 WMS 入账价口径 |
| 库存成本净变动 | 纳入范围内库存成本的净方向变化 | `库存成本流入 - 库存成本流出`；分类余额视角可用`月末库存成本 - 月初库存成本`交叉核对 | 月份 + 仓别/物料/分类 |
| 车间净耗用成本 | 车间本期实际耗用成本 | `领料成本 - 退料冲回成本 + 报废成本` | 月份 + 车间；数量按物料/单位 |
| 销售净额 | 销售出库扣销售退货的 WMS 销售价金额 | `出库销售额 - 退货销售额` | 月份 + 销售项目/客户/分类 |
| 销售净成本 | 销售出库成本扣退货成本 | `出库成本 - 退货成本` | 同上 |
| WMS 商品毛利估算 | WMS 销售价与来源成本的差额 | `销售净额 - 销售净成本` | 同上；明确非正式财务毛利 |
| 项目归属库存成本净变动 | 研发项目归属库存本期变化 | `交接入成本 + 退回成本 + 盘盈成本 - 领用成本 - 报废成本 - 盘亏成本` | 月份 + 研发项目 |
| 项目净耗用成本 | 研发项目本期实际耗用 | `领用成本 - 退回成本 + 报废成本` | 月份 + 研发项目 |
| 业务单据数 | 构成指标的真实业务单据数 | `COUNT(DISTINCT documentType, documentId)` | 任意汇总层 |

## 8. 推荐修改顺序

| 顺序 | 修改内容 | 原因 |
| --- | --- | --- |
| 1 | 删除`净生产`，拆分生产入库与采购净入库 | 概念最明显错误，且用户已经明确指出 |
| 2 | 删除跨物料总数量/净数量；只调查数量小数，暂不改取整格式 | 无量纲合计必须先删除；显示精度需先确认单位规则 |
| 3 | 拆分销售价、库存成本、采购/入库价，取消混合`总金额/净发生金额` | 这是仓库与财务能否真正对账的核心 |
| 4 | 统一车间净耗用公式并补报废 | 已有领域真源，属于实现偏离，不需要重新发明口径 |
| 5 | 修复趋势单据数、方向、RD/车间缺项 | 当前趋势图的名称和数据均不能可靠解释 |
| 6 | 修复首页退厂正向累计和库存健康粒度 | 首页是高频入口，误导范围大 |
| 7 | 研发项目金额改用实际成本，并补盘盈盘亏与净耗用 | 使项目成本台账与库存来源成本一致 |
| 8 | 记录实时月报、成本覆盖率和历史分类风险 | 实时月报与历史分类本轮不改，以导出归档流程和风险说明控制边界 |

## 9. 审核后剩余开放问题

全局 12 项及其他字段语义均已完成业务审核，决定见本文“业务审核结论”。当前只剩一个会改变成本口径的业务选择：

- 历史研发交接或项目动作没有`cost / costAmount`时，是将该成本显示为缺失并从成本合计中排除（保持实际成本口径纯净），还是回退使用录入`amount`（覆盖更完整但会混入非实际成本）？

在该问题确认前，文档和帮助文案不得把录入金额静默描述为实际成本。
