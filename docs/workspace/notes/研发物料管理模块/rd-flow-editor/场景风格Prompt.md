# 立体流程办公场景 · 风格 Prompt

风格标识：`SOFT-AXON-OFFICE-v1`  
版本：1.0 · 2026-09-15  
基准：[研发物料流程编辑器.html](../研发物料流程编辑器.html) 中的「3D 场景」。

用途：用于后续新增房间、家具、人物、流程动画及同类页面，统一视觉语言。本文只提供提示词与规范，不要求生成图片或更换渲染框架。

## 1. 风格定义

**柔和低多边形 × 正交轴测 × 微缩办公沙盘。**

像一座拿掉屋顶、可从斜上方观看的微型办公室：浅色底座、开放房间、简化家具、积木式小人。安静、清晰、亲和，带轻量经营模拟游戏的空间感，但服务于业务流程理解，不做游戏化炫技。

英文识别词：

`soft low-poly office diorama, orthographic axonometric view, roofless cutaway rooms, miniature block-style people, muted pastel palette, matte surfaces, restrained depth shading, readable workflow simulation`

没有直接复用或指定参考某个外部项目、美术资产包或品牌。当前实现是自写 Canvas 三维坐标投影；AntV X6 仅负责原二维流程编辑。风格不依赖 Canvas、Three.js 或其他具体框架。

## 2. 主 Prompt：直接复制

将下列占位内容替换后，整段交给设计或开发 Agent：

```text
请沿用 SOFT-AXON-OFFICE-v1，为【业务主题】设计或扩展立体流程场景。
本次范围：【新增 / 修改的区域、人物、家具、交互】。
实际流程与角色：【节点、连线、负责人、正常及异常分支；未提供的业务规则不得编造】。
交付形式：【交互页面 / 三维场景模块 / 静态概念图】。

视觉定位：
柔和低多边形、正交轴测视角、屋顶打开式微缩办公沙盘。整体像精巧但克制的办公模型，亲和而专业，不写实、不赛博、不做重度游戏界面。

镜头与空间：
从斜上方观看，能同时看到地面、家具顶面及两个侧面。
使用正交投影，无近大远小、无广角变形、无消失点；不要把“立体”理解为给平面卡片加阴影。
沿用基准镜头：水平朝向约 36°、相对水平面的俯视角约 38°。如做交互，俯视角可在 25°–65° 调节，默认不自动旋转。
保留有厚度的浅色整体底座，房间以低饱和地面分区、局部背墙和侧墙区分，去掉屋顶和遮挡观看的前墙。
房间之间有连续走廊与明确门洞。人物能走到工位，不能穿过墙体、桌面或货架。整体居中并完整入画，四周保留呼吸空间。

造型与比例：
家具以长方体、薄板和少量圆润几何体构成，结构简洁，顶面和侧面明暗可辨。
桌子必须有厚度与桌腿；电脑有屏幕和支架；货架有层板和立柱；箱子用少量封箱胶带或标签帮助识别。
人物使用球形头、简化块状躯干、短小四肢，轻微大头但不夸张；同类人物共享比例和细节密度。
用服装颜色及少量道具区分角色，不用写实面孔、复杂发丝或高度精细的身体模型。
植物仅用花盆和少量团块状树冠点缀，不增加密集叶片细节。

配色与材质：
大面积使用暖白、浅灰绿、浅木色；局部使用雾蓝、鼠尾草绿、灰紫、麦芽棕和浅橄榄。
整体低饱和，颜色分区清楚但不刺眼；不要让每个物体都有不同的鲜艳颜色。
基础地面 #f7f7ee，墙面 #e9eeea，底座 #c0d0c7，木桌 #d7b58a。
场景活动强调色使用深绿 #216e50 / 青绿 #58a891，异常路径使用柔和红 #ca776e。
人物或节点已有业务语义颜色时保留原含义，不为了统一视觉而改变业务色彩规则。
材质以哑光模型、浅木板、柔和纸箱及低反光屏幕为主，无金属镜面、强玻璃反射、复杂纹理或做旧污渍。

光影：
使用统一、温和的明暗逻辑：顶面较亮、侧面略暗，物体落地有轻量接触阴影，整体底座有克制投影。
人物和家具之间保持正确前后遮挡。不要厚黑描边、强烈高光、霓虹光晕、戏剧性明暗或模糊景深。

文字与界面：
区域名称保持面向屏幕的二维文字，不随地面倾斜或缩成难读的贴图。
中文无衬线字体；深灰绿正文、低对比辅助说明；文字清晰优先于装饰。
画面以场景为主，侧栏展示当前步骤、负责人、业务说明及步骤列表；操作集中在底部，避免 HUD、密集浮窗和过多卡片。
小屏完整展示场景，详情可下移；不裁掉房间来强行放大物体。

流程动作：
工位人物表示负责人，移动人物表示本次单据或物料交接，不表示某个真实员工全程代办所有角色。
单据阶段携带文件，实物阶段携带箱子或使用相应搬运道具。
动作顺序是“工位停留办理 → 沿通道移动 → 到下一节点交接”，步伐和手臂动作轻微，避免弹跳和无目的走动。
路线贴地且克制，常规为实线、异常为虚线；只强调当前相关路径。
按给定业务连线推进，分支可明确选择；无后续步骤即停止，不自行补齐循环、审批或退回规则。
交互版本保留暂停、单步、重播与速度控制；尊重减少动态效果设置。

一致性优先：
复用已有镜头、人物比例、色板、家具结构与光影逻辑。本次只更改明确指定的内容，不重做整个场景美术。
若需要升级精度、写实程度、投影方式或颜色体系，先说明与基准的差异，不静默更换风格。
```

## 3. 负面 Prompt / 禁止漂移项

可独立附加到生成或开发提示词末尾：

```text
避免：写实建筑效果图、电影级渲染、强透视、广角或鱼眼、纯正俯视平面图、自动旋转镜头、赛博朋克、深色科技大屏、霓虹发光、玻璃拟态、镜面金属、厚黑描边、像素画、全体素方块化、高饱和彩虹色、过度软糯的黏土玩具感、夸张大头萌系人物、写实人脸、复杂皮肤和毛发、密集装饰、悬浮家具、人物穿墙、错乱遮挡、强烈弹跳动画、流程线悬在空中、标签随地面倾斜、文字过小、满屏 UI 面板、无依据的业务步骤、外部品牌标志或水印。
```

“低多边形”不等于每个面都必须三角形化；“等距风格”不等于强制使用严格等距投影；“微缩”不等于幼儿玩具风格。

以下数值来自现有实现，用于对齐，而不是声称已使用物理灯光或完整三维引擎。

| 主仓交接区 | 麦芽棕 `#c09560` | `#eee5d6` |
| 供应商收货区 | 灰橄榄 `#939b70` | `#e8ebdc` |

### 几何与画面

- 投影：正交轴测；水平朝向 36°，默认俯视角 38°。这是视觉接近等距的轴测镜头，并非严格数学等距。
- 当前人物：约 56–58 场景单位高，头部直径约 18，躯干宽约 20；头高约占总身高三分之一。
- 当前桌子：宽 78、深 42，桌面底部离地 30、厚度 5。扩展家具时以同一人物作比例尺，场景单位不是米。
- 当前底座：810 × 480，厚约 15；六区采用两排三列，仅为本场景布局，不要求所有未来场景强制六区。
- 明暗：当前方块顶面 RGB 通道约 +16，两侧约 -18 / -34；这是简化着色，不是物理光照参数。
- UI：暖白与浅灰绿背景、深灰绿文字、绿色主要操作；中文使用 PingFang SC 等系统无衬线字体。原二维编辑器的蓝色 UI 不必随场景一起改色。
- 色彩优先级：房间柔和配色与业务状态色分开。移动人物当前沿用节点颜色，主流程蓝、异常红等语义不可随意重映射。

## 5. 扩展用短 Prompt

### 新增房间 / 工位

```text
沿用 SOFT-AXON-OFFICE-v1，在现有场景中新增【区域名称】，用于【真实业务职责】。
保留现有正交轴测镜头、整体底座、哑光材质、人物与桌椅比例。
从既有六组柔和色板中选择【色组】，复用现有家具结构，只增加说明职责所必需的【设备 / 道具】。
先保证通道、门洞、人物行动范围和标签清晰，再补少量装饰。
不新增业务规则，不改变其他房间的风格和颜色含义。
```

### 新增人物 / 动作

```text
沿用 SOFT-AXON-OFFICE-v1，新增【角色】或【动作】。
复用现有球形头、块状躯干、短四肢与轻微大头比例；用【服装色 / 道具】区分角色。
动作服务于【节点 / 交接关系】，采用轻微步伐、短暂停留与简化交接，不用夸张表情、弹跳或特效。
沿可通行走廊移动，正确处理门洞和前后遮挡；暂停时动作与流程状态同时冻结。
```

### 仅生成静态视觉参考

```text
按 SOFT-AXON-OFFICE-v1 绘制【业务主题】的静态视觉参考。
柔和低多边形微缩办公沙盘，正交轴测斜俯视，开放屋顶、局部墙体、浅色厚底座，完整入画。
使用统一比例的积木式小人、简化桌椅电脑与仓储设施；暖白、雾蓝、鼠尾草绿、浅木色，哑光表面、克制的面明暗和接触阴影。
表现【区域、人数和正在发生的业务动作】，保留通道和留白。
不生成界面截图、按钮、文字标签、品牌或水印；文字由后续页面排版添加。
这只是静态美术参考，不能代替可交互的流程场景。
```

## 6. 交付前一致性检查

- [ ] 镜头仍是斜俯视正交轴测，能辨认顶面与侧面，没有变成强透视或纯平面。
- [ ] 新旧人物的头身比例、家具尺度、材质精度一致。
- [ ] 新增物体仍使用同一套柔和色板与明暗规则，没有突然出现写实贴图或高亮反射。
- [ ] 主要房间与底座完整可见；标签面向屏幕且可读，小屏不横向溢出。
- [ ] 家具落地、遮挡合理，人物通过通道与门洞，不穿墙或踩过设备。
- [ ] 道具和动作能解释实际业务，不把单据流转误画成库存变动。
- [ ] 异常色和分支语义保留，流程顺序来自业务数据而不是动画脚本猜测。
- [ ] 扩展范围之外的镜头、人物、配色、UI 没有无理由重设计。
