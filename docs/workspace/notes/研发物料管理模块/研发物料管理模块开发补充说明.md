# 研发物料管理模块开发补充说明

**申请日期**：2026年9月12日　**编号**：待登记

**关联文档**：《仓库管理系统研发物料管理模块建设立项申请书》。本文档记录操作规则、核查事项与实施安排；建设必要性、目标与报批事项以立项申请书为准。

## 一 业务规则与功能细节

### 1.1 业务流程与角色边界

**项目与计划准备**：研发仓库管理员曹艳根据研发人员提供的物料需求维护项目资料、BOM 计划物料及参考成本，结合项目可用库存、实际耗用和在途采购查看缺口，为下列采购及库存流程提供依据。其他研发人员可在授权范围内查询项目与 BOM。BOM 表达计划，不直接产生库存变化。

1. **填写草稿**：研发人员填写研发采购申请草稿。
2. **复核修改**：曹艳查看并按实际需求修改。
3. **确认提交**：曹艳确认无误后提交。
4. **采购执行与跟踪**：采购部查看申请并维护“驳回”或“采购中”等采购状态、供应商、计划到货日期和采购信息。
5. **分批送货**：供应商分批送货至主仓。
6. **主仓入库**：仓库人员办理主仓入库。
7. **领料核对**：曹艳到主仓领取并负责物料核对。
8. **调入研发**：主仓人员点击“调入研发”，系统在同一业务动作中完成主仓减少和 研发仓库增加，不要求 研发仓库再次确认收货。
9. **研发仓库管理**：研发仓库管理员曹艳统一办理 研发仓库按研发项目领用、退料、报废、盘点、库存调整和查询；其他研发人员仅可查询。

**项目核对与分析**：依据交接、领退报废和盘点调整的实际记录，查询项目当前在库、净耗用及成本台账，并与 BOM 计划对照；内部调拨、实际耗用和盘点差异分别展示。

**申请人区分**：立项申请书的申请人由项目负责人崔永琪担任。采购单据中的“申请人”仍记录实际提出物料需求的研发人员；曹艳负责复核、修改和提交采购申请，不承担本立项申请人的职责。

**研发侧角色与权限**：采购申请复核、确认提交、领料核对和 研发仓库管理统一归属“研发仓库管理员”角色，由曹艳承担，并负责研发项目资料及 BOM 的系统维护。其他研发人员仅具有采购申请和查看权限：可新建、保存和修改本人或授权范围内的采购申请草稿，并查询授权范围内的采购进度、项目/BOM、库存和成本台账；申请由曹艳复核后正式提交，其他研发人员无复核提交、项目/BOM 维护及库存业务操作权限。

**采购业务审批边界**：本流程不设置系统审批流。采购申请提交后直接进入采购状态跟踪；采购部可以驳回申请或将其置为采购中，并持续维护采购执行信息。公司如有其他线下管理要求，可在原有渠道执行，但不作为本模块的审批接口、审批节点或审批状态同步建设内容。

**项目建设审批要求**：本项功能范围约定不免除本研发项目的立项、设计冻结和正式上线审批，项目审批按公司制度及总经理批准的程序办理。

### 1.2 功能细节与验证要求


| 功能        | 拟建设内容与主要验收口径                                                                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 研发采购申请    | 研发人员可新建和保存草稿；申请至少记录申请人、所属部门、研发项目、物料、规格、单位、数量、需求日期和用途。曹艳可查看、修改并提交；提交前校验必填项，提交后保留申请人和提交人记录。                                                                                       |
| 采购状态跟踪    | 采购部可查看已提交申请并维护采购状态，至少支持驳回、采购中及后续到货推进状态；记录供应商、采购数量、单价/金额、计划到货日期、实际到货数量、剩余数量和备注。可按需求日期、状态和是否延期筛选，直接回答“买没买、什么时候到”。                                                                 |
| 分批到货与主仓入库 | 供应商货物分批到货时，仓库人员按实际到货办理主仓入库，并关联原采购申请及对应物料行；系统累计已到货和未到货数量，禁止重复提交造成重复入库。仓库人员负责入库操作，不将物料核对责任写入仓库岗位。                                                                                 |
| 领料核对与调入研发 | 曹艳从主仓领取物料时负责核对品类、规格和数量；主仓人员点击“调入研发”后，系统自动完成主仓出库和 研发仓库入库，保留交接人员、时间、物料、数量和来源关系；研发仓库不再二次确认收货。                                                                                      |
| 研发项目与 BOM | 由研发仓库管理员曹艳维护研发项目主档、项目 BOM、计划数量、参考成本及厂家/链接/备注，支持缺口/补货查询；其他研发人员仅可查询。研发采购申请必须关联有效研发项目，项目名称和相关快照由项目资料带出，不使用自由文本替代项目关联。                                                              |
| 研发仓库日常管理  | 由研发仓库管理员曹艳统一办理 研发仓库按项目领用、退料、报废、盘点和库存调整，其他研发人员仅可查询；所有进入 研发仓库的物料、盘点/调整和后续项目动作均绑定研发项目。项目不是新的物理库存池，实际库存范围仍为主仓和 研发仓库。                                                                |
| 项目耗用与成本台账 | 按项目及物料展示交接入项目、当前在库、已领、已退、已报废和净耗用的数量及成本，与 BOM 计划数量及参考成本对照；内部调拨与项目实际耗用分别记录，盘点差异单独留痕，成本结果可追溯至实际物料业务记录。                                                                             |
| 退回与异常     | 退回主仓及公司级退货由主仓人员操作；系统保留退回原因、经办人、时间和库存反向流水。支持驳回、取消、更正、分批到货和异常备注，已发生的库存事实不得被静默覆盖。                                                                                                  |
| 查询、报表与留痕  | 支持按采购申请、研发项目、物料、供应商、状态和日期查询，并可下钻到到货、调入研发和项目物料动作。分别展示申请数量、采购数量、已到货数量、已调入数量和未到货数量；金额按申请/采购/入库阶段区分，不重复相加，也不把申请或采购金额称为实际付款金额。                                                       |
| 权限        | 研发仓库管理员曹艳统一负责采购申请复核、修改和提交、领料核对、项目/BOM 维护及 研发仓库项目领用、退料、报废、盘点、库存调整和查询；其他研发人员仅可维护本人或授权范围内的采购申请草稿及查询授权数据。采购人员维护采购执行状态和采购信息；主仓人员办理主仓入库、调入研发、退回主仓及公司级退货；系统管理员负责配置、排障和审计。越权修改必须被拒绝并留痕。 |




### 1.3 本期排除项

- 系统审批流、审批节点配置、飞书审批编号关联、审批接口和审批状态同步。
- 财务付款、发票、报销、完整财务核算及供应商年度评价。
- 生产车间独立库存或生产车间采购流程。生产车间不属于本项目业务范围。
- 开放式多仓、库位管理、复杂物流调度、消息队列、微服务拆分和复杂 BPM。

## 三 实施计划草案

**启动条件与时间口径**：T0 为总经理书面批准立项、人员和环境落实后的启动日；立项时应明确业务需求、验收标准及资源安排，第 1 周在批准范围内细化需求基线。

**计划编排说明**：以下为批准后拟执行的计划，具体日期由项目负责人在启动时填写。

**周期安排依据**：4 周覆盖本期完整业务链路，基于现有 WMS 的主数据、库存、权限和研发项目能力复用，并以落实并行开发与测试支持为前提。第 1 周完成需求与方案确认并启动基础功能开发，第 2 周完成采购协同主流程并并行推进项目、库存与成本功能，第 3 周完成剩余功能、联调、回归和整改，第 4 周开展受控试用、验收及正式上线。开发过程中同步验证分批到货、退回、重复提交和盘点调整，核对采购进度、两仓库存、项目余料与成本统计的一致性；业务人员按周反馈，设计冻结与正式上线签批按节点提前安排。

**项目组管理**：项目组随立项批准成立并登记，完成结项前不得解散。


| 节点           | 建议时间           | 主要成果与完成条件                                                                                |
| ------------ | -------------- | ---------------------------------------------------------------------------------------- |
| 立项传签确认       | T0 前           | 完成需求初评、人员与资源及优先级确认，由总经理签批项目分类、立项和软件关卡对应关系。                                               |
| 需求确认与基线      | 第 1 周前半周       | 依据批准的建设范围，另行确认并记录角色、字段、状态、项目/BOM 范围、分批到货口径和验收标准。                                         |
| 方案设计与基础开发    | 第 1 周          | 完成页面、接口、数据、权限、库存过账及成本口径方案；确认主仓入库、调入研发、退回、项目耗用与盘点调整边界，启动项目/BOM、权限和采购草稿等基础功能开发。            |
| 采购申请与状态跟踪    | 第 2 周          | 完成草稿、曹艳复核提交、采购状态、供应商/到货计划、分批到货、主仓入库和延期查询；本周安排 1 次设计评审，可传阅签字，检查方案可行性、接口匹配和依赖风险。           |
| 研发项目、库存与成本管理 | 第 2 周至第 3 周前半周 | 并行完成研发项目、BOM 与缺口查询、主仓到 研发仓库自动过账及项目归属、项目领退报废、盘点调整和项目成本台账，分批交付联调。                          |
| 集成测试与整改      | 第 3 周          | 对已交付功能滚动联调，完成主流程、分批到货、重复提交、驳回、退回、权限测试，核对 BOM 计划、项目耗用、盘点调整、两仓库存与成本台账，并完成现有 WMS 回归测试及问题整改。 |
| 设计冻结传签确认     | 第 3 周末、受控试用前   | 完成问题整改、试用软件版本及相关技术文件登记发布、业务与运维可行性确认；附技术负责人书面技术意见，由总经理签批后冻结版本并开展受控试用。                     |
| 试用、验收与正式上线确认 | 第 4 周          | 研发、采购和仓库人员试用确认，在《交付与验收记录》中记录试用结论，完成数据核对、试用问题整改与复测、培训、备份、回退与验收准备；由总经理签批正式上线后于本周完成部署发布并归档。 |
| 运行反馈、评价与结项   | 上线后 1 个月内      | 项目负责人在《交付与验收记录》中一次性汇总运行效果、问题处理及结项意见，经产品决策委员会评审、总经理批准后完成结项归档。                             |




## 四 管理安排与待确认事项

**软件关卡对应**：结合内部软件交付特点，原立项草案建议将“试产前设计冻结确认”对应为“受控试用前设计冻结确认”，将“试产后转产确认”对应为“试用验收后正式上线确认”，该建议须经总经理确认，本说明不代表已获批准。

**特批要求**：需跳过关卡或免用制度表单的，按第四十九条另行取得总经理书面特批并登记，不由项目负责人自行豁免。
