## 一 项目背景与建设必要性

目前研发采购主要通过在线 Excel 表格跟踪，采购、到货和物料使用情况需要跨岗位核对，现有管理方式存在以下问题：

1. **采购进度缺乏透明度**：研发人员需逐项联系采购人员，才能掌握采购状态及预计到货时间，信息更新不及时容易影响研发安排。
2. **项目物料缺口难以准确掌握**：项目需求、现有库存和已采购未到货数量缺少统一对照，容易出现漏采、重复采购或临时补货。
3. **物料流转及结存情况缺乏连续记录**：到货、转入研发仓库不等同于项目实际使用，需要结合领用、退回、报废和盘点记录，准确掌握物料所属项目、实际耗用量及结存量。
4. **项目物料成本难以准确核对**：采购金额不能直接代表项目实际耗用成本，需要区分未使用、已使用和已报废物料，才能与原计划进行比较。

通过本项目，预期减少重复沟通和重复登记，及时识别物料缺口及到货延期，提高余料利用和盘点核对效率，并为研发备料及物料费用分析提供依据。

## 二 建设目标、主要内容与业务边界

本期覆盖研发物料从计划、采购、入库到使用和成本查询的完整过程，主要建设内容如下：

| 业务能力 | 建成后的使用效果 |
| --- | --- |
| 项目物料计划 | 按研发项目记录物料需求、需求数量及预计成本，结合现有库存、实际耗用和已采购未到货情况，识别物料缺口及补充需求。 |
| 采购申请与进度查询 | 研发人员填写采购需求，经研发仓库管理员核对后提交采购；采购人员更新执行进度，相关人员可直接掌握采购状态、预计到货时间、累计到货量和未到货量。 |
| 到货与仓库交接 | 记录分批到货、主仓入库及转入研发仓库的情况，同步更新两个仓库的库存数量，掌握物料所在仓库、所属研发项目及交接记录；同时支持记录退回主仓和向供应商退货。 |
| 项目物料使用 | 按项目记录领用、退料和报废，分别统计领用量、退料量、报废量及结存量，区分仓库间转移与项目实际耗用。 |
| 盘点与差异处理 | 按项目和物料核对系统记录与实物数量，记录盘点差异及处理原因，调整后仍可追溯数量变化。 |
| 项目物料成本查询 | 按项目查看结存、实际耗用及报废物料成本，并与计划进行比较；相关数量和费用可追溯至对应的采购、出入库及使用记录。 |

**主要业务分工**：曹艳统一负责采购需求核对提交、项目物料清单维护、领料核对及研发仓库管理；徐文静负责采购执行和进度更新；田晓晶负责主仓出入库及与研发仓库的交接；其他研发人员负责提出采购需求并查询相关信息。

**本期不包含**：线上采购审批及与其他审批系统对接，财务付款、发票、报销及完整财务核算，供应商年度评价，生产车间采购或库存管理，以及扩展到其他仓库、细分仓内存放位置或复杂运输调度。相关业务仍按公司原有规定办理。

本申请书用于说明建设必要性、目标和预期结果。具体操作规则、系统设计、测试要求和实施安排另行在开发文档中记录。
